03 · GPU memoryFlashAttention Explained

A GPU has fast memory and big memory.Never both in the same place.

Registers

256 KB / SM

Private to each thread. Hold the values being multiplied right now.

SRAM · shared memory

192 KB / SM · ~19 TB/s

Scratchpad shared by one SM's threads. You choose what goes in.

L2 cache

40 MB · whole chip

Shared by all SMs. Mostly managed by hardware, not your code.

HBM · “GPU memory”

40–80 GB · 1.5–2.0 TB/s

Off-chip stacks. Weights, activations, Q, K, V live here.

CPU DRAM

>1 TB · 12.8 GB/s

Host memory over PCIe. Far too slow for the inner loop.

One SM’s SRAM: ~10× faster than HBM, ~200,000× smaller.NVIDIA A100 · Dao et al., 2022

05 · Why standard attention is slowFlashAttention Explained

Standard attention writes N² to HBM.Then reads it back, kernel after kernel.

Kernel 1

QKᵀ writes S, the full N × N table, to HBM.

Kernels 2–4

Mask, softmax, dropout each read N² and write N².

Kernel 5

PV reads P one last time to make the output.

Eight N² trips through HBM, for one layer's forward pass.Standard implementation · Dao et al., 2022, Alg. 0

06 · The ideaFlashAttention Explained

Never build the full table.Work tile by tile inside SRAM.

1 · Hold

Load one Q tile. It stays in SRAM for its whole row.

2 · Stream

K, V tiles flow past. Each score tile is used, then dropped.

3 · Write once

Store the O tile. The N × N table never reaches HBM.

Fuse every step into one kernel, so scores never leave the chip.Dao et al., 2022 · loop order of FlashAttention-2

07 · Online softmax, simplyFlashAttention Explained

Online softmax in three moves.Check the leader, add, divide at the end.

1

Check the leader. A bigger score arrived? Shrink both jars by one factor.

2

Add the new keys. Points into jar 1, points × value into jar 2.

3

After the last block, divide. Answer = jar 2 ÷ jar 1. Exact.

Per row, SRAM holds just a leader and two jars.
Same answer as normal softmax, exactly. Full maths: Appendix A.Milakov & Gimelshein, 2018 · Dao et al., 2022
08 · The algorithmFlashAttention Explained

One kernel. Q, K, V in. O out.Everything else stays on chip.

L1–3

Pin a Q tile. Start m at −∞, ℓ and O at zero, all in SRAM.

L4–6

Stream K, V tiles. A small score tile S exists only on chip.

L7–12

Online softmax. Rescale old ℓ and O by c, then add the new block.

L13–14

Divide once, write once. Save O and L = m + log ℓ.

HBM sees Q, K, V, O and L. Never S, never P.After Dao, 2023, Algorithm 1 · simplified

Appendix A1 · Online softmax in detailFlashAttention Explained

Softmax needs the whole row.A tile only sees part of it.

One row of 12 scores · 3 blocks of 4
1 / 3
Safe softmax
pᵢ = e^(sᵢ − m) ÷ ℓ

m = max of the row · ℓ = Σ e^(sⱼ − m)

m

Needs the row maximum

Without it e^s overflows: FP16 tops out near e^11.

ℓ

Needs the sum over every key

Every weight is divided by it.

Both are final only after the last tile, unless we fix them as we go.
Partial rows give wrong weights. We need a softmax that updates.Milakov & Gimelshein, 2018 · toy scores
Appendix A2 · Subtract the maxFlashAttention Explained

Subtract the max: same answer.But every number stays at most 1.

Four scores · shift them all by k
+0
Largest e^s0
Largest e^(s − m)1
k

A shift cancels out

e^(s+k) = e^s · e^k. The e^k sits on top and bottom.

m

So shift by −max

The biggest term becomes e⁰ = 1. Nothing can overflow.

A different max only changes one common factor. Remember that.
Softmax ignores a shared shift, so we may pick any reference point.FP16 max = 65,504 ≈ e^11.09
Appendix A3 · Change of unitsFlashAttention Explained

A new max is just a change of units.One factor c converts all the old work.

Bars = e^(s − reference max)
3.1
Analogy · currency

You saved 1.62 in “old-max” money. A new max is a new currency: convert once at rate c, keep adding.

1

e^(s − m_old) · c = e^(s − m_new)

Where c = e^(m_old − m_new).

2

ℓ_new = c · ℓ_old + Σ new

Shrink the old sum, add the new terms.

One multiply fixes the whole past.
When the max rises, every old term shrinks by the same c.e^a · e^b = e^(a+b) · toy scores
Appendix A4 · Fixing the outputFlashAttention Explained

The output gets the same correction.Divide by ℓ once, at the very end.

Accumulators for one query row · d = 4
O

O = Σ e^(s − m) · v

Same weights as ℓ, each times its value vector v.

c

So O needs the same c

New max? Multiply ℓ and every entry of O by c.

÷

Normalise once

Keep O unnormalised in SRAM. Output = O ÷ ℓ after the last block.

ℓ and O share one correction factor, so they stay in step.Dao, 2023 · FlashAttention-2, §3.1
